# 会員退会（アカウント削除）対応手順書

社内向け手順書。デタウリ.Detauri 会員から退会・個人情報削除の請求を受けた際の運用フロー。

- 受付窓口: メール `nkonline1030@gmail.com` / 電話 `090-5820-1803`（平日 10:00〜18:00）
- 根拠: 個人情報保護法（2022年改正・2026年改正）／プライバシーポリシー第6項・第8項
- 関連シート:
  - 顧客管理シート（個人情報保管）
  - 依頼管理シート（注文履歴・税法上7年保存対象）

## 0. 全体方針

- **手動運用**: 自動退会フォームは未実装。すべて窓口経由で受け付ける
- **本人確認必須**: 登録メールアドレス本人からの請求であることを確認してから処理する
- **税法保存とのバランス**: 取引記録（受付番号・取引日・金額）は税法上7年保存。**個人特定情報のみ削除・匿名化**する
- **対応期限**: 個情法上「合理的な期間内」。実務上は **2営業日以内に着手・5営業日以内に完了** を目安とする

## 2. 本人確認

- 登録メールアドレス宛に確認メールを送信し、**そのアドレスからの返信** で確認する
  （他のアドレスから来た請求は、登録アドレスへの確認返信を求める）
- 電話受付の場合は、登録メールアドレス宛にワンタイムコードを送り、口頭で読み上げてもらう
- 本人確認できない場合は、**処理を開始しない**。理由を伝えて再依頼してもらう

## 3. 未処理注文チェック（削除前の必須確認）

依頼管理シートを開き、当該メールアドレス（D列）で絞り込み:

| ステータス（P列） | 入金確認（R列） | 発送（M列） | 対応 |
|---|---|---|---|
| 依頼中 | 未入金 | — | **削除NG**: 注文キャンセル処理を先に実行 |
| 完了 | 入金済 | 未発送 | **削除NG**: 発送完了を待つ |
| 完了 | 入金済 | 発送済み | **削除OK** |

- 未処理注文がある場合は、お客様に状況を連絡し、注文完了後に再度退会処理する旨を伝える
- 「キャンセルして即時退会したい」と希望された場合は、注文キャンセル → 返金処理 → 退会の順で実行

## 4. 顧客管理シートの匿名化

顧客管理シートで該当行を特定し、以下の列を **空欄または匿名化文字列** に書き換える:

| 列 | 内容 | 処理後 |
|---|---|---|
| A | 顧客ID | **残置**（依頼管理との紐付け用、ID自体は個人を特定しない） |
| B | メールアドレス | `deleted-{顧客ID}@example.invalid` |
| C | パスワードハッシュ | 空欄 |
| D | 氏名 | 空欄 |
| E | 電話番号 | 空欄 |
| F | 郵便番号 | 空欄 |
| G | 住所 | 空欄 |
| K | セッションID | 空欄 |
| L | セッション有効期限 | 空欄 |
| M | ポイント残高 | `0` に変更 |
| 退会日（追加列）| 退会日 | 処理日（YYYY-MM-DD） |

- 行自体は削除せず、上記マスキングのみ実行（依頼管理との外部キー整合のため）
- ポイント残高がある場合は、お客様に確認のうえ失効扱いとする（規約上、退会で失効）

## 5. 依頼管理シートのメール列マスク

依頼管理シートで当該メールアドレスの行を全件抽出し、D列（連絡先メール）を以下に置換:

```
deleted-{受付番号}@example.invalid
```

- A列（受付番号）、B列（依頼日時）、L列（合計金額）は **税法上7年保存** のため残す
- H列（商品名）も統計目的で残してよい（個人特定情報ではない）

## 8. 例外対応

### 8.1 「過去の注文も含めて完全削除してほしい」と要請された場合

- 税法上の保存義務（取引日から7年）を説明し、**取引記録の完全削除はできない** ことを伝える
- 個人特定情報（氏名・住所・メール等）の削除のみで対応する旨を再説明
- それでも納得されない場合は、個情委・税理士に相談

### 8.2 死亡された会員の遺族からの請求

- 死亡診断書または戸籍謄本のコピーで死亡確認
- 相続人の本人確認書類で続柄確認
- 確認できれば通常フローで処理

### 8.3 不審な請求（なりすまし疑い）

- 登録メールアドレス本人からの確認が取れない場合は処理しない
- 警察・個情委から開示要請があった場合は、要請文書を確認のうえ法務に相談
